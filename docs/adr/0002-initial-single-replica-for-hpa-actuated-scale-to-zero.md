# Start `job-worker` at `replicas: 1` So HPA Actuates Initial Scale-to-Zero

`Deployment/job-worker` is declared with `replicas: 1` in `manifests/02-worker-and-hpa.yaml` rather than `replicas: 0`. If a Deployment is created at `0` replicas before `autoscaling-metrics-adapter` has published initial metric samples—or is manually scaled to `0` via `kubectl scale --replicas=0`—GKE's HPA controller treats the zero count as an External Scale-to-Zero Override (`ScalingActive: False`, reason `ScalingDisabledReplicaCountZero` / `ScalingDisabledExternalScaleToZero`) and pauses autoscaling until an operator manually scales the Deployment to at least `1` replica. Starting at `replicas: 1` allows HPA itself to actuate the initial `1 -> 0` scale-down (`ScaledToZero: True`, `ScalingActive: True`) as soon as the `AutoscalingMetric` pipeline reports `0` pending jobs.
